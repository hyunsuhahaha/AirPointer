# AirPointer

## 출품용 브라우저 체험 개편

첫 화면에서 **30초 체험하기 → 임시저장 필터 → 새로고침 실행 → 방금 오류 찾아줘**를 선택하면
설치·가입·화면 공유 없이 실제 AI 분석과 근거 확인을 체험할 수 있습니다.
사건 작업대는 확인된 사실·추정·다음 확인 사항을 구분하며, 선택한 근거 이미지가 포함된
단일 HTML 보고서 다운로드와 텍스트 복사를 제공합니다. 실제 작업은 **내 화면에서 사용하기**로 시작합니다.
실제 PiP 검증은 **PiP용 개발 작업 탭 열기**로 `/developer-lab`을 열고, 메인 화면에서 해당 탭을 공유한 뒤 같은 조작을 수행합니다. PiP에서 리플레이를 선택하고 질문하면 실제 녹화 버퍼를 분석합니다.
Screen Memory 영구 저장은 기본값이 꺼진 별도 확장 옵션입니다.
구현 범위와 검증 결과는 [출품 경험 개편](docs/competition-redesign.md)에 정리했습니다.

## 브라우저 모드 방향

순수 브라우저 경험은 다음 두 런타임으로 분리하는 방향을 확정했다. 이 구분은 아직 코드에
완전히 적용되지 않았으므로 아래 대회 제출용 절차는 현재 구현을 설명한다.

- **교육 모드:** 카메라 미리보기와 MediaPipe 손 인식을 켜고 손짓을 배우고 체험한다.
- **작업 모드:** 화면 공유와 Document PiP만 사용한다. 개발·문서·운영 작업용이며 카메라
  권한을 요청하지 않고 카메라 스트림과 손 인식 엔진을 실행하지 않는다. 화면 공유가 시작되면
  PiP가 자동으로 열리고 작업 모드의 브라우저 조작은 PiP 버튼으로만 수행한다.

교육 모드에서 작업 모드로 전환할 때 카메라 UI만 숨기는 것이 아니라 스트림, HandLandmarker,
Worker, 타이머, Canvas 버퍼를 모두 종료·해제해야 한다. 개발·문서·운영은 작업 모드 내부의
프로필이며 별도의 최상위 모드는 아니다. 상세 경계와 현재 구현과의 차이는
[브라우저 전용 vs 네이티브 앱](docs/browser-vs-native-capabilities.md#확정된-브라우저-제품-구조-교육-모드와-작업-모드)에 정리했다.

## 대회 제출용: 설치 없는 브라우저 체험

공개 체험의 우선 경로는 `web/`입니다. 방문자는 AirPointer.exe, 확장 프로그램 또는
Codex를 설치할 필요가 없습니다. 서버에는 `OPENAI_API_KEY`가 설정되어 있어야 합니다.

1. 웹에서 화면 공유를 시작하고 화면·창·탭 중 하나를 선택합니다.
2. 최근 1·3·5분은 브라우저 메모리의 순환 버퍼에 쌓입니다.
3. 화면 공유가 시작되면 **항상 위 캡처 버튼**이 자동으로 켜지고 Document PiP 창이 열립니다.
   브라우저가 자동 열기를 차단했을 때만 같은 스위치를 눌러 다시 시도합니다.
4. 현재 화면·최근 리플레이·영역 선택 중 하나로 분석을 요청합니다. 영역 선택은 고정한
   공유 화면 미리보기에서 드래그하거나 방향키(Shift: 크기 조절)로 조정한 뒤 확정합니다.
5. PiP에서 **질문만 보내기**로 새 이미지를 첨부하지 않고 이어서 질문할 수 있습니다.
   이전 대화는 최근 8개 메시지/6,000자 범위의 텍스트로만 전달되며 과거 이미지는 재첨부하지 않습니다.
6. 개인정보 보호가 켜져 있으면 브라우저 로컬 OCR이 API 키·토큰·이메일·전화번호·카드번호를
   찾아 가린 사본만 전송합니다. 사용자가 모든 프레임에서 항상 가릴 영역도 직접 지정할 수 있습니다.
7. AI 답변의 화면 근거를 누르면 로컬 Replay Capsule에서 해당 시점 전후 2초를 0.25초 간격으로
   다시 디코딩하는 **근거 타임머신**이 열립니다. 이 9장은 추가로 서버에 전송되지 않습니다.
8. PiP의 **AI 탐색 실시간** 영역에서 대표 프레임 확인, 시간 구간 재탐색, 오류 후보 발견,
   코드 영역 확대, 근거 확보가 시작·완료 상태와 프레임 예산을 포함해 순서대로 표시됩니다.
9. 설치 없이 체험할 때는 **개발 오류·결제 운영·재고 시트·화상 회의** 중 하나를 고를 수 있습니다.
   각 시나리오는 0.5초짜리 핵심 단서를 포함한 실제 이미지 프레임을 생성할 뿐, 분석 결과는
   미리 정해두지 않습니다. 화면 공유와 동일한 API·프레임 예산·재탐색·크롭·가림·근거 경로를 사용합니다.
10. 아래 `LOCAL SCREEN MEMORY` 작업대에서는 OCR 화면 검색, DVR 시간여행, 영구 북마크·태그,
    활동 요약, Markdown 개발 리포트, 로컬 Agent API/MCP를 사용할 수 있습니다. 화면 공유 없이도
    **샘플 개발 기록으로 체험** 버튼으로 모든 화면을 확인할 수 있습니다. 자세한 사용법과 API는
    [docs/screen-memory.md](docs/screen-memory.md)를 참고하세요.

Screen Memory MCP는 브라우저 IndexedDB를 직접 읽지 않습니다. 브라우저 화면 공유와 AirPointer
Companion이 함께 실행되어 SQLite로 동기화된 기록, 그리고 AirPointer 자체 화면 캡처가 실행 중
자동으로 적재하는 기록(둘 다 온디바이스 OCR 포함) 모두 Codex 또는 Claude의 로컬 stdio MCP에서
검색할 수 있습니다. `python -m airpointer.mcp_install`로 두 Agent의 MCP 설정에 한 번에 등록할
수 있습니다. 샘플 기록 동기화만 의도적으로 지원하지 않습니다. 정확한 지원 매트릭스는
[Screen Memory 지원 범위](docs/screen-memory.md#지원-범위)를 참고하세요.

PiP는 지원되는 데스크톱 Chrome/Edge에서 제공되며, 메인 페이지를 닫으면 함께 닫힙니다.
공유 중지·새 공유·PiP 닫기 시 PiP 대화는 초기화됩니다. 순수 브라우저 단축키 모드는 제공하지
않으며, 전역 단축키가 필요하면 AirPointer가 필요합니다. 실제 화면 공유 권한과 OS별 항상 위 동작은
브라우저·운영체제 조합에 따라 달라질 수 있으므로 배포 환경에서 별도 실기 확인이 필요합니다.

## Portable Windows companion

Build the no-installer companion with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-portable.ps1
```

The result is `portable\AirPointer.exe`. Run it once to register the per-user
`airpointer://` protocol. After that, the website's gesture switch requests
camera access and launches the transparent companion overlay with
`airpointer://start`; turning the switch off sends `airpointer://stop`.

> 웹 출품작 이름: **방금그거뭐였지**

Windows용 웹캠 제스처 캡처 + Agent Replay 도구입니다. OS 마우스 커서는 조작하지 않습니다.
설정창에는 손 위치를 확인할 수 있는 미러 카메라 미리보기가 표시됩니다.
`Agent Replay` 탭에서는 최근 화면을 최대 5분 동안 로컬 순환 버퍼에만 보관합니다. 주먹→손바닥으로
영역 선택을 시작하면 화면이 잠기고, 이후에는 실제 마우스로 클릭 드래그하여 영역을 지정하고
놓으면 확정됩니다(오른쪽 클릭으로 취소). 손바닥을 2초 유지하면 최근 구간의 핵심 프레임을
선택한 Codex 작업으로 전달합니다.

## 실행

설치가 끝난 PC에서는 `AirPointer.bat`을 더블클릭하면 콘솔 창 없이 실행됩니다.

Python 3.11 권장(MediaPipe 호환 범위가 가장 안정적):

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python airpointer_launcher.py
```

## 시작 모드: 제스처 / 단축키

AirPointer를 켜기 전에 두 모드 중 하나를 고릅니다(웹 컨트롤의 "시작 모드"나 네이티브 설정창의
`START MODE`에서 선택 — 켜져 있는 동안은 전환할 수 없습니다, 얹어 쓰는 토글이 아니라 둘 중 하나를
고르는 방식입니다):

- **제스처 모드**: 웹캠으로 손 동작을 인식합니다(기존 방식).
- **단축키 모드**: 카메라를 전혀 켜지 않고, 전역 단축키로 캡처를 트리거합니다. 기본값은
  `Ctrl+Alt+S`(현재 화면), `Ctrl+Alt+D`(최근 리플레이), `Ctrl+Alt+R`(영역 선택)이며, 웹
  컨트롤에서 단축키 입력창에 원하는 조합을 눌러 각 동작별로 바꿀 수 있습니다(브라우저에서
  설정한 값이 로컬 설정보다 우선합니다). 이미 다른 프로그램이 같은 조합을 전역 단축키로 쓰고
  있으면 그 동작의 등록만 실패하고 나머지 동작은 정상 동작합니다.

## 웹 버전 실행 및 배포

`web/`은 AI Championship 2026 제출용 Next.js 앱입니다. 브라우저의 화면 공유로 최근 1~5분을
메모리 순환 버퍼에 보관합니다. 선택한 Codex 작업으로 현재 화면 또는 최근 5/15/30/60초의 원본
Replay Capsule을 보내는 Agent 전송과, Responses API로 화면을 분석하는 기능은 서로 분리되어 있습니다.
카메라를 허용하면 손바닥 2초 유지로 최근 구간을 고정합니다. 이후 추천 질문을 고르거나 직접
프롬프트를 입력해 확인해야 선택한 Codex 작업으로 화면 맥락과 질문이 함께 전송됩니다.

```powershell
cd web
Copy-Item .env.example .env.local
# .env.local의 OPENAI_API_KEY를 실제 키로 변경
npm install
npm run dev
```

Agent 전송에는 API 키 대신 로그인된 Codex CLI가 필요합니다. Codex 데스크톱 앱이 설치돼 있어도
`codex` 실행 파일이 PATH에 없을 수 있습니다(버전별 해시 폴더 아래 설치되는 경우). 이 경우
`web/.env.local`에 `CODEX_EXECUTABLE=<codex.exe 전체 경로>`를 추가하세요
(예: `%LOCALAPPDATA%\OpenAI\Codex\bin\<hash>\codex.exe`). 웹 화면에서 `Codex Agent` 작업을
선택한 다음 화면 공유와 제스처를 켜세요. 선택한 작업이 실행 중이면 캡처를 유지한 채 자동으로
재시도합니다. Replay Capsule에는 개요 이미지와 타임스탬프가 있는 원본 WebM 조각이 들어가며,
Agent는 `-0.5초`처럼 원하는 과거 시점을 전체 해상도 프레임으로 다시 조회할 수 있습니다.
`OPENAI_API_KEY`를 쓰는 분석도 브라우저가 변화 감지 알고리즘으로 대표 프레임을 최대 6장만 먼저
보냅니다. AI가 그 사이 장면이나 고해상도 확대가 더 필요하다고 판단하면 18장 프레임 예산과
최대 6회 탐색 안에서 반복 요청하고, 브라우저가 메모리의 로컬 WebM에서 필요한 프레임만 꺼냅니다.
영상 전체는 분석 서버로 보내지 않습니다. 최종 근거를 누르면 해당 시점 전후 2초를 로컬에서만
재생하며, 개인정보 보호가 켜진 경우 OCR과 사용자 지정 영역으로 가린 사본만 API에 전달합니다.

Vercel에서는 Root Directory를 `web`으로 지정하고 `OPENAI_API_KEY`를 환경 변수로 추가하면 됩니다.
화면 공유와 카메라는 보안 컨텍스트가 필요하므로 배포 환경에서는 HTTPS를 사용해야 합니다.

앱과 대상 프로그램의 권한 수준이 같아야 화면 캡처 오버레이의 클릭이 정상 동작합니다.

브라우저만으로 되는 것과 AirPointer 설치 시 추가되는 것의 구체적인 경계는
[docs/browser-vs-native-capabilities.md](docs/browser-vs-native-capabilities.md) 참고.

## 현재 범위

- 주 모니터 한 대
- 첫 번째로 감지된 손 한 개
- MJPG 640×360@60 캡처와 320×180 손 추적
- MediaPipe handedness로 오른손만 선택해 왼손으로 추적 대상이 바뀌는 현상 방지
- 1초 MP4 조각으로 구성된 로컬 화면 순환 버퍼(기본 3분, 250MB 상한)
- 주먹→손바닥으로 영역 선택 모드 진입, 이후 실제 마우스 클릭 드래그로 영역 지정 및 확정(오른쪽 클릭 취소)
- 손바닥 유지 최근 5/15/30/60초 전송
- 실행 전 제스처(카메라) 모드와 단축키(카메라 없음) 모드 중 하나를 선택(아래 "시작 모드" 참고)
- 화면 캡처와 리플레이 캡처 모두 전송 전 질문 입력 프롬프트를 거침(기존엔 화면 캡처만 즉시 전송)
- 전송 시 최근 30초 안의 창 전환·클릭 이력을 컨텍스트로 함께 첨부
- 캡처 순간 화면에 드래그로 선택해둔 텍스트가 있으면 그대로 함께 전송(아래 "선택 텍스트" 참고)
- (기본 꺼짐) 최근 30초 복사 이력도 같은 컨텍스트에 포함 가능(`clipboard_history_enabled`,
  아래 "복사 이력" 참고)
- Codex 대화 검색 선택(기본값은 현재 Codex Desktop에 열려 있는 대화)과 이미지 첨부,
  전송 실패 시 수동 재시도(`Retry Send`); 검색어가 없을 때는 Codex Desktop 사이드바처럼
  프로젝트별로 묶여 표시(기본 접힘, "더 보기"로 펼침)

## Agent Replay

네이티브 앱은 Codex CLI/App Server나 web 앱의 HTTP 연결을 전혀 쓰지 않습니다. 대신 화면
캡처를 클립보드에 넣고 Codex Desktop 입력창에 실제 Ctrl+V와 Enter를 보내는 방식으로
전달합니다(사람이 직접 붙여넣는 것과 동일한 입력) — 그래서 **`npm run dev`가 켜져 있을
필요가 없고**, Codex 스레드의 writer lock을 가로채거나 다른 앱에서 "열려 있음" 상태가 되는
문제도 생기지 않습니다.

**대신 Codex Desktop 앱이 실행 중이어야 합니다.** `Agent Replay` 탭에서 `Refresh Tasks`를
누르면 Codex Desktop 사이드바의 대화 목록을 그대로 읽어와 검색 가능한 목록으로 보여줍니다.
검색창을 비워두면(기본값) 지금 Codex Desktop에서 열려 있는 대화로 그대로 전송되고, 대화
이름을 검색해 고르면 전송 직전에 Codex Desktop이 그 대화로 자동 전환된 뒤 전송됩니다. 화면
버퍼는 AirPointer 추적을 시작할 때 켜지고 중지 또는 종료 시 삭제됩니다. Agent에는 시간순
핵심 PNG 프레임 최대 6장이 한 번에 첨부됩니다. 화면 우측 상단의 `BUFFER` HUD로 기록 여부를
항상 확인할 수 있습니다.

화면 캡처와 리플레이 캡처 모두, 전송 직전 최근 30초 안의 창 전환·클릭 이력을 한 줄 컨텍스트로
함께 보냅니다(사용자가 어떤 화면·버튼을 거쳐 지금 상태에 왔는지 Codex가 픽셀만 보고 짐작하지
않도록). 리플레이 전송 중 실제로 화면 변화가 감지된 프레임이 있으면 "화면 변화 감지: N번째
프레임, 오른쪽 아래 영역"처럼 위치를, 가능하면 "화면 변화 감지: N번째 프레임, 저장 버튼"처럼
UI Automation으로 읽은 실제 요소 이름을 위치 힌트로 같은 컨텍스트 줄에 덧붙입니다. 접근성
트리를 아예 노출하지 않는 앱(일부 게임, 커스텀 렌더링 UI)에서는 같은 화면 영역을 Windows
자체 온디바이스 OCR로 다시 읽어 그 텍스트를 대신 씁니다 — 두 경로 모두 비전 모델 호출 없이
로컬에서만 처리됩니다(자세한 설계와 실측치는
[docs/replay-change-detection.md](docs/replay-change-detection.md) 참고). Codex Desktop 창을 처음 찾는 조회는 Electron의 접근성(UI Automation) 트리를 그 자리에서
새로 구축하느라 20~30초까지 걸릴 수 있는데, 앱을 켤 때 백그라운드에서 미리 한 번 조회해 두므로
(warmup) 실제 첫 전송에서는 이 지연이 거의 나타나지 않습니다. 이후 전송들도 찾아둔 창을
캐싱해 재사용합니다.

### 선택 텍스트

단축키/제스처를 트리거한 그 순간 화면 어딘가에 드래그로 선택해둔 텍스트가 있으면, 캡처
프롬프트 입력창이 뜨기 직전(아직 원래 앱에 포커스가 있을 때) 그 내용을 읽어서 창 전환·클릭
이력과 같은 컨텍스트 줄에 `선택 텍스트: ...`로 붙입니다. 화면이 복잡하거나 글자가 작아
스크린샷만으로는 어디를 가리키는지 애매한 경우, 또는 화면 밖으로 스크롤된 긴 로그/에러를
가리키는 경우에 특히 유용합니다(픽셀을 다시 읽을 필요 없이 정확한 텍스트가 그대로 전달됨).

두 가지 방식을 순서대로 시도합니다:

1. **UI Automation TextPattern** — 읽기만 하는 방식이라 부작용이 없지만, 이걸 구현한
   앱에서만 동작합니다(Windows 11 기본 메모장 등에서 확인됨).
2. **Ctrl+C 폴백** — 위 방식이 안 통하는 앱을 위한 보조 수단으로, 실제로 포커스된 곳에
   Ctrl+C를 보낸 뒤 클립보드를 읽고 원래 상태로 즉시 복원합니다. 안전을 위해 다음 조건에서만
   시도합니다: 포커스된 컨트롤이 일반 텍스트 계열(Edit/Document/Text/ComboBox)일 것,
   그리고 탐색기(파일 탐색기)가 아닐 것(탐색기에서 Ctrl+C는 "파일 복사"를 뜻하므로 절대
   보내지 않음). 이 과정에서 클립보드에 원래 있던 내용(텍스트뿐 아니라 복사해둔 파일 목록
   등 다른 형식도 포함)은 항상 그대로 복원되며, `clipboard_history_enabled`가 켜져 있어도
   이 순간의 복사는 "사용자가 복사한 것"으로 기록되지 않습니다.

선택된 게 없거나 두 방식 모두 실패하면 그냥 조용히 생략되며, 이 때문에 캡처 자체가 막히는
일은 없습니다. 별도 설정 없이 항상 켜져 있습니다 — 클립보드 이력과 달리 "지금 화면에서
가리키고 있는 것" 이상은 읽지 않기 때문입니다.

### 복사 이력 (기본 꺼짐)

Windows 클립보드는 슬롯이 하나뿐이라("A 복사 → B 복사"하면 A는 이미 사라짐), 전송 시점에
클립보드를 한 번만 읽으면 가장 최근 것 하나만 보입니다. 여러 번 복사한 걸 순서대로("A → B →
C") 전달하려면 AirPointer가 켜져 있는 동안 클립보드 변화를 계속 지켜보면서 직접 30초짜리
이력을 쌓아야 하는데, 이 내용은 창 제목·클릭한 버튼보다 훨씬 민감할 수 있어서(비밀번호,
계좌번호 등) **기본값은 꺼짐**입니다. `settings.json`에서 `"clipboard_history_enabled": true`로
켜면 창 전환·클릭 이력과 같은 컨텍스트 줄에 `복사: A → B → C` 형태로 붙습니다. 전송 중
AirPointer 자신이 이미지/프롬프트를 붙여넣느라 클립보드에 쓰는 것은 이 이력에 안 잡히도록
구분합니다.
