# 현재 방식 vs. 계층형 작업·의도 추론 예비 평가

측정일: 2026-09-07
모델: `gpt-5.4-mini`

## 질문

화면 변화 알고리즘이 고른 동일한 최근 화면을 입력했을 때, 현재의 직접 분석 프롬프트보다
`현재 작업 → 하위 목표 → 마지막 시도 → 막힌 지점 → 추정 의도`를 먼저 구성하도록 한
프롬프트가 실제로 더 정확한가?

이 평가는 **기존 중요 순간 선별 알고리즘을 변경하지 않는다.** 두 조건 모두 같은 시간순
대표 프레임 4장을 받는다.

## 방법

- 업무·개발·운영 상황을 포함한 합성 화면 시나리오 21개를 Chrome으로 렌더링했다.
- 기준선은 현재 `/api/analyze`의 질문 없는 리플레이 동작과 같은 방식으로, 핵심 변화·문제·원인·다음 행동을 바로 답하게 했다.
- 실험 조건은 같은 한 번의 모델 호출에서 `MomentContext`를 먼저 구조화하고 답하게 했다.
- 두 결과의 조건 이름을 숨기고 순서를 번갈아 섞은 뒤 별도 모델 호출로 블라인드 채점했다.
- 현재 작업, 인과관계/마지막 시도, 막힌 지점, 의도/다음 행동, 근거 충실성을 각각 0~2점으로 평가했다.
- 최초 21개 전체 탐색 후 차이가 관찰된 9개를 각 3회 반복했다.

## 결과

### 최초 전체 탐색: 21개 × 1회

| 지표 | 현재 방식 | 계층형 추론 | 차이 |
|---|---:|---:|---:|
| 평균 정확도 | 9.29/10 | 9.95/10 | +0.67 |
| 평균 응답 지연 | 2.65초 | 4.04초 | +53% |
| 평균 출력 토큰 | 188 | 404 | +115% |

이 단계는 한 번만 실행한 탐색 결과이므로 효과 크기의 근거로 사용하지 않는다.

### 차이 관찰 사례 반복: 9개 × 3회

| 지표 | 현재 방식 | 계층형 추론 | 차이 |
|---|---:|---:|---:|
| 평균 정확도 | 9.52/10 | 9.74/10 | +0.22 |
| 평균 응답 지연 | 2.91초 | 4.10초 | +41% |
| 평균 입력 토큰 | 2,905 | 3,035 | +4.5% |
| 평균 출력 토큰 | 191 | 436 | +129% |

27쌍 중 점수 기준으로 계층형 추론 6승, 현재 방식 1승, 20무였다. 블라인드 평가자의
최종 선호는 계층형 7회, 현재 방식 1회, 무승부 19회였다.

### 잘못 정의된 일정 시나리오 제외

`calendar-conflict`의 정답은 Mina의 14시 충돌을 현재 막힘으로 정의했지만, 마지막 화면은
이미 15시 30분에 전원 참석 가능 상태까지 진행했고 남은 일은 저장이었다. 실제 두 출력은
이를 올바르게 읽었으므로 이 사례의 점수는 제품 의사결정에서 제외한다.

나머지 8개 × 3회(24쌍)는 다음과 같다.

| 지표 | 현재 방식 | 계층형 추론 | 차이 |
|---|---:|---:|---:|
| 평균 정확도 | 9.67/10 | 9.96/10 | **+0.29** |
| 현재 작업 | 1.875/2 | 2.000/2 | +0.125 |
| 인과관계·마지막 시도 | 1.917/2 | 2.000/2 | +0.083 |
| 막힌 지점 | 1.958/2 | 2.000/2 | +0.042 |
| 의도·다음 행동 | 1.917/2 | 2.000/2 | +0.083 |
| 근거 충실성 | 2.000/2 | 1.958/2 | **-0.042** |

블라인드 선호는 계층형 6회, 현재 방식 0회, 무승부 18회였다. 즉 75%는 실질적 차이를
찾지 못했고, 25%에서 계층형 출력이 더 낫다고 판단했다.

## 관찰

- 효과는 주로 오류 자체보다 **사용자가 궁극적으로 하려던 일**을 명시하는 데서 나왔다.
  첨부파일 누락, 세션 만료, 디자인 내보내기처럼 화면의 오류와 상위 목적이 다른 사례에서
  계층형 출력이 더 안정적이었다.
- blocker 판별은 현재 방식이 이미 매우 강했다. 새 구조의 개선 폭은 0.042/2에 불과했다.
- 구조화 필드를 강제로 모두 채우면 화면에 없는 행동까지 매끄럽게 추정하거나 불필요한
  확인 문구를 보탤 위험이 있었다. 근거 충실성이 소폭 하락한 이유다.
- 합성 화면은 글자가 크고 사건 순서가 명확하다. 실제 공유 화면의 작은 OCR, 가려진 장면,
  여러 앱 전환에서는 절대 점수가 더 낮아질 수 있다.
- 생성 모델과 채점 모델이 같고, 반복 대상을 최초 결과를 보고 선택했으므로 정식 통계적
  유의성 검정이나 일반화 성능 주장에는 사용할 수 없다.

## 결정

현재 결과만으로 전체 분석 경로를 계층형 방식으로 교체할 근거는 부족하다. 정확도 이득은
약 2.9%p인 반면 지연은 41%, 출력 토큰은 129% 늘었다.

권장안은 다음과 같다.

1. 기존 6장 선별과 일반 분석은 그대로 유지한다.
2. 계층형 추론을 모든 요청에 강제하지 않는다.
3. 사용자가 질문 없이 제스처만 보낸 경우, 또는 여러 앱/단계를 거친 경우에만 선택적으로 사용한다.
4. 사용자에게는 긴 `MomentContext`를 출력하지 않고 Agent 입력 메타데이터로만 사용한다.
5. `unknown`을 허용하고 각 필드에 근거 프레임을 연결해 과잉 추론을 억제한다.
6. 실제 사용자 화면 로그를 익명화해 최소 50개 이상 확보한 뒤 다시 평가한다.

## 재현

평가 하네스는 `web/scripts/eval-intent-inference.mjs`에 있다. `.env.local`의
`OPENAI_API_KEY`를 읽지만 키 내용은 출력하지 않는다.

```powershell
cd web
node scripts/eval-intent-inference.mjs
```

결과 원본은 실행할 때마다 `web/.data/evals/intent-inference/latest.json`에 저장된다.
